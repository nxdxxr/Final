# โครงงานระยะที่ 3: นำเสนอโครงงาน (Final Integration & Project Defense)

## รายละเอียด

โครงงานระยะที่ 3 เป็นระยะสุดท้ายของโครงงานที่พัฒนาต่อเนื่องมาตั้งแต่ระยะที่ 1 (`wk05-project-phase1.md`: DB/Requirement) และระยะที่ 2 (`wk10-project-phase2.md`: Docs/DX & Integration) โดยเพิ่มโมดูล Microservices จากสัปดาห์ที่ 13 เข้ามารวมเป็นระบบเดียว เพิ่ม Frontend เล็ก ๆ ที่เรียกใช้ API ของตนเองจริง จากนั้นขัดเกลาให้สมบูรณ์และนำเสนอผลงานต่อผู้สอน

โครงงานระยะที่ 3 นี้แบ่งเป็น 3 ส่วนที่วัดผลคนละ CLO

| ส่วน                              | CLO ที่วัด   | คะแนน |
| --------------------------------- | ------------ | ----- |
| ส่วนที่ 1: Final Integration      | CLO8 (PLO14) | 5     |
| ส่วนที่ 2: Client-Frontend        | CLO6 (PLO10) | 10    |
| ส่วนที่ 3: Project Defense        | CLO7 (PLO13) | 5     |

## ส่วนที่ 1: Final Integration (Full Stack Sync)

### สิ่งที่ต้องส่ง

1. **โค้ดรวมที่สมบูรณ์** — รวมโมดูลทั้งหมดจากระยะที่ 1-2 และสัปดาห์ที่ 13 (Microservices) เข้าเป็นระบบเดียวที่รันได้จริงโดยไม่มี merge conflict หลงเหลือ
2. **ตรวจสอบความสอดคล้องระหว่างเอกสารกับโค้ดจริง (Swagger/Code Match)** — อัปเดต OpenAPI Specification จากระยะที่ 2 ให้ตรงกับ endpoint ล่าสุดทั้งหมด รวม endpoint ที่เพิ่มจาก Microservices
3. **รายงาน Test Coverage Baseline** — รัน test suite ทั้งหมด (จากสัปดาห์ที่ 9 และ 13) แล้วสรุปเปอร์เซ็นต์ coverage พร้อมระบุจุดที่ยังไม่มี test ครอบคลุม

### เกณฑ์การให้คะแนนส่วนที่ 1

คะแนนเต็ม 5 คะแนน (เป็นส่วนหนึ่งของ CLO8 ซึ่งรวม 15 คะแนนตลอดภาคการศึกษาจากโครงงาน 5 จุด ได้แก่ ระยะที่ 1 — DB/Requirement (5 คะแนน), ระยะที่ 2 — Docs/DX (2.5 คะแนน), ระยะที่ 2 — Integration (2.5 คะแนน), และระยะที่ 3 — Final Integration (5 คะแนน, ส่วนนี้))

| รายการ                                                   | คะแนน |
| -------------------------------------------------------- | ----- |
| ระบบรวมทำงานได้จริงโดยไม่มี conflict หรือ error หลงเหลือ | 3     |
| เอกสาร API ตรงกับโค้ดจริงทั้งหมด (Swagger/Code Match)    | 1     |
| รายงาน Test Coverage ครบถ้วนและสะท้อนสถานะจริงของโค้ด    | 1     |
| **รวม**                                                  | **5** |

## ส่วนที่ 2: Client-Frontend (เรียกใช้ API จริง)

ดูตัวอย่างโค้ดและเทคนิคที่เพียงพอสำหรับทำส่วนนี้ได้ที่เอกสารเสริม [wk15-frontend.md](wk15-frontend.md) (HTML/CSS/JavaScript ล้วน) หรือ [wk15-frontend-react.md](wk15-frontend-react.md) (React) เลือกใช้ตามเทคโนโลยีที่ถนัด

### สิ่งที่ต้องส่ง

1. **หน้าเว็บ Frontend อย่างง่าย** (เช่น HTML/CSS/JavaScript ล้วน, React, หรือเทคโนโลยีอื่นที่ถนัด — ไม่จำกัดเฟรมเวิร์ก) ที่เรียกใช้ API ของระบบโครงงานตนเองจริงอย่างน้อย 3 endpoint ครอบคลุมทั้งการอ่าน (GET) และการเปลี่ยนแปลงข้อมูล (POST/PUT/DELETE อย่างน้อย 1 รายการ)
2. **การออกแบบหน้าจอให้เหมาะกับผู้ใช้จริง** — แสดงข้อมูลในรูปแบบที่อ่านง่าย มีการจัดการสถานะ loading/error ให้ผู้ใช้เห็นความคืบหน้าหรือข้อผิดพลาดอย่างชัดเจน ไม่ปล่อยหน้าจอค้างเงียบเมื่อเรียก API ไม่สำเร็จ
3. **แบบฟอร์มรับข้อมูลจากผู้ใช้** (สำหรับ endpoint ที่ส่งข้อมูล) พร้อมตรวจสอบความถูกต้องเบื้องต้นฝั่ง Frontend ก่อนส่งไปยัง API

### เกณฑ์การให้คะแนนส่วนที่ 2

คะแนนเต็ม 10 คะแนน (เป็นคะแนนทั้งหมดของ CLO6 ตลอดภาคการศึกษา)

| รายการ                                                                                    | คะแนน  |
| ----------------------------------------------------------------------------------------- | ------ |
| เรียกใช้ API จริงได้ครบตามที่กำหนด (อย่างน้อย 3 endpoint รวม GET และการเปลี่ยนแปลงข้อมูล) | 4      |
| ออกแบบหน้าจอเหมาะกับผู้ใช้ แสดงสถานะ loading/error ชัดเจน                                 | 3      |
| แบบฟอร์มรับข้อมูลทำงานถูกต้อง พร้อมตรวจสอบความถูกต้องเบื้องต้น                            | 3      |
| **รวม**                                                                                   | **10** |

## ส่วนที่ 3: Project Defense (การนำเสนอ)

### รูปแบบการนำเสนอ

นำเสนอโครงงานของตนเองต่อหน้าผู้สอน ใช้เวลา 5-7 นาที ประกอบด้วย

1. **Demo ระบบสด** (3-4 นาที) — สาธิตการทำงานของระบบตั้งแต่ต้นจนจบอย่างน้อย 1 use case หลัก
2. **ตอบคำถาม** (2-3 นาที) — ตอบคำถามจากผู้สอนเกี่ยวกับการออกแบบสถาปัตยกรรม การตัดสินใจทางเทคนิค และปัญหาที่พบระหว่างพัฒนา

### เกณฑ์การให้คะแนน (Scoring Rubrics)

คะแนนเต็ม 5 คะแนน (เป็นคะแนนทั้งหมดของ CLO7 ตลอดภาคการศึกษา — วัดผลที่ W15 ครั้งเดียวผ่าน Project Defense)

| รายการ                                                           | คะแนน |
| ---------------------------------------------------------------- | ----- |
| Demo ทำงานได้จริงสด ไม่ใช้สไลด์อธิบายแทนการสาธิตจริง             | 2     |
| อธิบายการออกแบบสถาปัตยกรรมและเหตุผลการตัดสินใจทางเทคนิคได้ชัดเจน | 2     |
| ตอบคำถามได้ตรงประเด็น สะท้อนว่าเข้าใจระบบที่ตนเองพัฒนาจริง       | 1     |
| **รวม**                                                          | **5** |
