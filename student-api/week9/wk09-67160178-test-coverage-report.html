2. การวิเคราะห์ Branch ที่ขาดหายไปใน app.js (Detailed Branch Coverage Analysis)

จากการวิเคราะห์ Uncovered Branches ในไฟล์ app.js พบว่ากิ่งเงื่อนไขที่ขาดหายไปเกิดจากการตรวจสอบข้อมูลนำเข้าที่ไม่ถูกต้อง (Validation Errors), การตรวจสอบ Header และการตอบสนองต่อข้อผิดพลาด (Error Responses) โดยมีรายละเอียดการเพิ่มเทสทั้ง 8 กรณีดังนี้:

กรณีทดสอบที่ 1: ตรวจสอบ Header Content-Type ใน Middleware requireJson

• Branch ที่ครอบคลุม: บรรทัดที่ 45-54 เงื่อนไข if (!req.is("application/json")) ฝั่ง True

• Branch เดิมที่ขาด: ไม่มีเทสที่ส่ง Content-Type อื่น โค้ดในบล็อกปฏิเสธและคืน 415 จึงไม่เคยถูกทดสอบ

• Test ที่เขียนเพิ่ม: ส่งคำขอ POST /api/v1/students พร้อม Header Content-Type: text/plain ยืนยันการตอบกลับ HTTP 415 UNSUPPORTED_MEDIA_TYPE

กรณีทดสอบที่ 2: ตรวจสอบ Fallback ของ Request Method ใน requireJson

• Branch ที่ครอบคลุม: บรรทัดที่ 45 เงื่อนไข methodsWithBody.includes(req.method) ฝั่ง False

• Branch เดิมที่ขาด: การทดสอบว่าเมธอดแบบ GET/DELETE จะไม่ถูกดักตรวจ Content-Type

• Test ที่เขียนเพิ่ม: ส่งคำขอ GET /api/v1/students โดยไม่ระบุ Content-Type ยืนยันว่าสามารถเรียก next() เข้าทำงานได้ปกติ

กรณีทดสอบที่ 3: ค้นหานักศึกษาด้วย ID ที่ไม่มีในระบบ (GET /api/v1/students/:id)

• Branch ที่ครอบคลุม: บรรทัดที่ 235-245 เงื่อนไข if (!student) ฝั่ง True เมื่อค้นหาไม่พบ

• Branch เดิมที่ขาด: เดิมทดสอบเฉพาะ ID ที่มีอยู่จริง ทำให้เงื่อนไขแจ้งเตือนไม่พบข้อมูลไม่เคยถูกเรียก

• Test ที่เขียนเพิ่ม: ส่งคำขอ GET /api/v1/students/9999 ยืนยันการตอบกลับ HTTP 404 STUDENT_NOT_FOUND

กรณีทดสอบที่ 4: การตรวจสอบข้อมูลบังคับไม่ครบถ้วนใน POST /api/v1/students

• Branch ที่ครอบคลุม: บรรทัดที่ 258-270 ตรรกะ if (!name || !major || !email) ฝั่ง True

• Branch เดิมที่ขาด: ทดสอบเฉพาะการส่ง Body ที่สมบูรณ์ ตรรกะตรวจข้อมูลว่างจึงยังไม่ถูกประเมิน

• Test ที่เขียนเพิ่ม: ส่งคำขอ POST โดยไม่ส่งฟิลด์ email ยืนยันการตอบกลับ HTTP 400 VALIDATION_ERROR

กรณีทดสอบที่ 5: การตรวจจับอีเมลซ้ำซ้อนในระบบ (POST /api/v1/students)

• Branch ที่ครอบคลุม: บรรทัดที่ 272-280 เงื่อนไข if (isDuplicate) ฝั่ง True

• Branch เดิมที่ขาด: เดิมสร้างอีเมลแบบ unique เสมอ ทำให้บล็อกป้องกันข้อมูลซ้ำไม่ทำงาน

• Test ที่เขียนเพิ่ม: ส่งคำขอ POST ด้วยอีเมล somchai@example.com ที่มีอยู่แล้ว ยืนยันการตอบกลับ HTTP 409 DUPLICATE_EMAIL

กรณีทดสอบที่ 6: การลบข้อมูลที่ไม่พบในระบบ (DELETE /api/v1/students/:id)

• Branch ที่ครอบคลุม: บรรทัดที่ 372-380 เงื่อนไข if (index === -1) ฝั่ง True

• Branch เดิมที่ขาด: เดิมทดสอบลบเฉพาะ ID ที่มีจริง ทำให้กิ่งตรวจสอบ ID สูญหายไม่ถูกประเมิน

• Test ที่เขียนเพิ่ม: ส่งคำขอ DELETE /api/v1/students/9999 ยืนยันการตอบกลับ HTTP 404 STUDENT_NOT_FOUND

กรณีทดสอบที่ 7: การดักจับ Route ที่ไม่มีอยู่จริง (404 Fallback Middleware)

• Branch ที่ครอบคลุม: บรรทัดที่ 761-770 ใน Middleware app.use((req, res) => { ... })

• Branch เดิมที่ขาด: ไม่เคยมีการเรียก URL นอกเหนือจากที่ระบุใน Router

• Test ที่เขียนเพิ่ม: ส่งคำขอ GET /api/v1/non-existent-route ยืนยันการตอบกลับ HTTP 404 ROUTE_NOT_FOUND ตามมาตรฐาน JSON

กรณีทดสอบที่ 8: การจัดการข้อผิดพลาดระบบ (Global Error Handler)

• Branch ที่ครอบคลุม: บรรทัดที่ 774-788 ในเงื่อนไข const statusCode = err.status || err.statusCode || 500

• Branch เดิมที่ขาด: Error Handler ทำงานเฉพาะเมื่อระบบขัดข้องรุนแรง

• Test ที่เขียนเพิ่ม: ส่งคำขอที่มีรูปแบบ Malformed JSON Body เพื่อให้ Express ส่ง Error เข้า Global Error Handler และยืนยันการตอบกลับ HTTP 400/500 อย่างถูกต้อง
