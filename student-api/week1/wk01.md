## 1. HTTP Lifecycle (วงจรชีวิตของการสื่อสารแบบ HTTP)

### 1.1 HTTP คืออะไร

HTTP (HyperText Transfer Protocol) เป็นโพรโทคอลระดับแอปพลิเคชัน (Application Layer) ที่ใช้ในการสื่อสารระหว่างไคลเอนต์ (client) เช่น เว็บเบราว์เซอร์หรือแอปพลิเคชันมือถือ กับเซิร์ฟเวอร์ (server) โดยทำงานอยู่บนโพรโทคอล TCP/IP เป็นโพรโทคอลแบบ **stateless** กล่าวคือ แต่ละคำขอ (request) จะไม่มีการจดจำสถานะของคำขอก่อนหน้า เซิร์ฟเวอร์จึงต้องอาศัยกลไกอื่น เช่น cookie, session หรือ token เพื่อจดจำสถานะของผู้ใช้งาน (จะกล่าวถึงรายละเอียดเรื่อง JWT Authentication ในสัปดาห์ที่ 6)

### 1.2 ขั้นตอนการทำงานของ HTTP แบบ Request-Response

การสื่อสารแบบ HTTP มีขั้นตอนหลักดังนี้

1. **DNS Resolution** — ไคลเอนต์แปลงชื่อโดเมน (เช่น `api.example.com`) เป็นหมายเลข IP ผ่านระบบ DNS
2. **TCP Connection (Three-way Handshake)** — ไคลเอนต์และเซิร์ฟเวอร์สร้างการเชื่อมต่อ TCP ด้วยกระบวนการ SYN, SYN-ACK, ACK
3. **TLS Handshake (กรณี HTTPS)** — หากใช้ HTTPS จะมีการเจรจาการเข้ารหัสข้อมูลก่อนเริ่มส่งข้อมูลจริง
4. **ส่ง HTTP Request** — ไคลเอนต์ส่งคำขอไปยังเซิร์ฟเวอร์ ประกอบด้วย Method, URL, Header และ Body (ถ้ามี)
5. **เซิร์ฟเวอร์ประมวลผล** — เซิร์ฟเวอร์รับคำขอ ตรวจสอบเส้นทาง (route) ประมวลผลตาม logic ที่กำหนด เช่น เชื่อมต่อฐานข้อมูล
6. **ส่ง HTTP Response** — เซิร์ฟเวอร์ส่งผลลัพธ์กลับ ประกอบด้วย Status Code, Header และ Body
7. **ปิดหรือคงการเชื่อมต่อ** — ขึ้นอยู่กับ Header `Connection` เช่น `keep-alive` เพื่อใช้ connection ซ้ำสำหรับคำขอถัดไป

```
Client                                Server
  |------ TCP Handshake (SYN/ACK) ------->|
  |<------------- ACK --------------------|
  |------ HTTP Request (GET /users) ----->|
  |                                        |  (ประมวลผล)
  |<----- HTTP Response (200 OK) ----------|
  |                                        |
```

### 1.3 ความสำคัญต่อการพัฒนา Backend API

นักพัฒนา Backend จำเป็นต้องเข้าใจ HTTP lifecycle เนื่องจาก API ที่พัฒนาขึ้นทำหน้าที่เป็น "เซิร์ฟเวอร์" ที่ต้องรับคำขอ ประมวลผล และตอบกลับให้ถูกต้องตามมาตรฐาน ความเข้าใจผิดในขั้นตอนนี้มักนำไปสู่ปัญหา เช่น การตั้งค่า Status Code ผิด หรือการไม่ปิด response ทำให้ client ค้าง (hang)

## 2. โครงสร้างของ HTTP Request และ HTTP Response

### 2.1 โครงสร้าง HTTP Request

HTTP Request ประกอบด้วย 4 ส่วนหลัก

```
POST /api/v1/users HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

{
  "name": "สมชาย ใจดี",
  "email": "somchai@example.com"
}
```

| ส่วนประกอบ                         | คำอธิบาย                                                                                                                                      |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **Request Line**                   | ประกอบด้วย HTTP Method (`POST`), เส้นทาง (`/api/v1/users`) และเวอร์ชันของ HTTP (`HTTP/1.1`)                                                   |
| **Headers**                        | ข้อมูลเมทาดาทาของคำขอ เช่น `Content-Type` (ประเภทข้อมูลที่ส่ง), `Authorization` (ข้อมูลยืนยันตัวตน), `Accept` (ประเภทข้อมูลที่ต้องการรับกลับ) |
| **Body**                           | ข้อมูลที่ส่งไปพร้อมคำขอ ใช้ในกรณี Method ที่มีการส่งข้อมูล เช่น `POST`, `PUT`, `PATCH`                                                        |
| **Query String / Path Parameters** | ข้อมูลเพิ่มเติมที่แนบไปกับ URL เช่น `/api/v1/users?page=2` (query string) หรือ `/api/v1/users/42` (path parameter)                            |

### 2.2 HTTP Methods ที่ใช้บ่อยในการพัฒนา API

| Method | ความหมาย                                        | ตัวอย่างการใช้งาน            |
| ------ | ----------------------------------------------- | ---------------------------- |
| GET    | ขอข้อมูล โดยไม่มีผลข้างเคียง (safe, idempotent) | ดึงรายการผู้ใช้ทั้งหมด       |
| POST   | สร้างข้อมูลใหม่                                 | เพิ่มผู้ใช้ใหม่              |
| PUT    | แก้ไขข้อมูลทั้งหมดของ resource (idempotent)     | แก้ไขข้อมูลผู้ใช้ทั้งระเบียน |
| PATCH  | แก้ไขข้อมูลบางส่วนของ resource                  | แก้ไขเฉพาะอีเมลของผู้ใช้     |
| DELETE | ลบข้อมูล (idempotent)                           | ลบผู้ใช้                     |

หมายเหตุ: หัวข้อการออกแบบ URI และการเลือกใช้ HTTP Method อย่างถูกต้องตามหลัก RESTful จะกล่าวถึงโดยละเอียดในสัปดาห์ที่ 3

### 2.3 โครงสร้าง HTTP Response

```
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/v1/users/42

{
  "id": 42,
  "name": "สมชาย ใจดี",
  "email": "somchai@example.com"
}
```

| ส่วนประกอบ      | คำอธิบาย                                                                   |
| --------------- | -------------------------------------------------------------------------- |
| **Status Line** | ประกอบด้วยเวอร์ชัน HTTP และ Status Code พร้อมข้อความอธิบาย (Reason Phrase) |
| **Headers**     | ข้อมูลเมทาดาทาของผลลัพธ์ เช่น `Content-Type`, `Content-Length`             |
| **Body**        | ข้อมูลผลลัพธ์ที่ส่งกลับ มักอยู่ในรูปแบบ JSON สำหรับ API สมัยใหม่           |

### 2.4 HTTP Status Code ที่ควรรู้จัก

| กลุ่ม | ความหมาย                                    | ตัวอย่าง                                           |
| ----- | ------------------------------------------- | -------------------------------------------------- |
| 1xx   | ข้อมูลระหว่างดำเนินการ (Informational)      | 100 Continue                                       |
| 2xx   | สำเร็จ (Success)                            | 200 OK, 201 Created, 204 No Content                |
| 3xx   | การเปลี่ยนเส้นทาง (Redirection)             | 301 Moved Permanently, 304 Not Modified            |
| 4xx   | ข้อผิดพลาดจากฝั่งไคลเอนต์ (Client Error)    | 400 Bad Request, 401 Unauthorized, 404 Not Found   |
| 5xx   | ข้อผิดพลาดจากฝั่งเซิร์ฟเวอร์ (Server Error) | 500 Internal Server Error, 503 Service Unavailable |

การเลือกใช้ Status Code ที่ถูกต้องเป็นส่วนสำคัญของการออกแบบ API ที่ดี เนื่องจากช่วยให้ผู้พัฒนาฝั่ง client ทราบผลลัพธ์ของคำขอได้อย่างชัดเจนโดยไม่ต้องอ่าน body เพียงอย่างเดียว

## 3. การติดตั้งและตั้งค่า Node.js และ Express

### 3.1 Node.js คืออะไร

Node.js คือ runtime environment สำหรับรันโค้ด JavaScript ฝั่งเซิร์ฟเวอร์ (server-side) โดยใช้ JavaScript engine ชื่อ V8 ของ Google Chrome จุดเด่นคือการทำงานแบบ non-blocking I/O และ event-driven ทำให้เหมาะสำหรับการพัฒนา API ที่ต้องรองรับการเชื่อมต่อจำนวนมากพร้อมกัน

### 3.2 Express คืออะไร

Express เป็นเฟรมเวิร์กสำหรับ Node.js ที่ช่วยลดความซับซ้อนในการเขียน HTTP server ด้วยตนเอง โดยมีความสามารถหลัก ได้แก่ ระบบ routing, middleware pipeline และการจัดการ request/response ที่ใช้งานง่าย เป็นหนึ่งในเฟรมเวิร์กที่ได้รับความนิยมสูงสุดสำหรับการพัฒนา Backend API ด้วย Node.js

### 3.3 ขั้นตอนการติดตั้ง

**ขั้นตอนที่ 1: ตรวจสอบและติดตั้ง Node.js**

ดาวน์โหลดและติดตั้ง Node.js เวอร์ชัน LTS (Long Term Support) จากเว็บไซต์ทางการ จากนั้นตรวจสอบเวอร์ชันที่ติดตั้งด้วยคำสั่ง

```bash
node -v
npm -v
```

**ขั้นตอนที่ 2: สร้างโปรเจกต์ใหม่**

```bash
mkdir backend-api-week01
cd backend-api-week01
npm init -y
```

คำสั่ง `npm init -y` จะสร้างไฟล์ `package.json` ซึ่งเก็บข้อมูลของโปรเจกต์และรายการ dependency โดยอัตโนมัติ

**ขั้นตอนที่ 3: ติดตั้ง Express**

```bash
npm install express
```

**ขั้นตอนที่ 4: (แนะนำ) ติดตั้งเครื่องมือช่วยพัฒนา**

```bash
npm install --save-dev nodemon
```

`nodemon` เป็นเครื่องมือที่ช่วยรีสตาร์ตเซิร์ฟเวอร์อัตโนมัติเมื่อมีการแก้ไขไฟล์ ทำให้ไม่ต้องหยุดและรันเซิร์ฟเวอร์ใหม่ด้วยตนเองระหว่างพัฒนา

จากนั้นเพิ่ม script ในไฟล์ `package.json`

```json
{
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js"
  }
}
```

## 4. Routing Basics (พื้นฐานการกำหนดเส้นทาง)

### 4.1 การสร้าง Express Application เบื้องต้น

ไฟล์ `index.js`

```javascript
const express = require("express");
const app = express();
const PORT = process.env.PORT || 3000;

// Middleware สำหรับแปลง request body ที่เป็น JSON
app.use(express.json());

// Route พื้นฐาน
app.get("/", (req, res) => {
  res.send("ยินดีต้อนรับสู่ API สำหรับการพัฒนา Backend");
});

app.listen(PORT, () => {
  console.log(`Server กำลังทำงานที่ http://localhost:${PORT}`);
});
```

รันเซิร์ฟเวอร์ด้วยคำสั่ง

```bash
npm run dev
```

### 4.2 การกำหนด Route ตาม HTTP Method

```javascript
// GET: ดึงรายการข้อมูลทั้งหมด
app.get("/api/v1/students", (req, res) => {
  res.status(200).json({
    message: "ดึงข้อมูลนิสิตทั้งหมดสำเร็จ",
    data: [
      { id: 1, name: "สมชาย ใจดี" },
      { id: 2, name: "สมหญิง รักเรียน" },
    ],
  });
});

// GET: ดึงข้อมูลตาม Path Parameter
app.get("/api/v1/students/:id", (req, res) => {
  const studentId = req.params.id;
  res.status(200).json({
    message: `ดึงข้อมูลนิสิตรหัส ${studentId} สำเร็จ`,
    data: { id: Number(studentId), name: "สมชาย ใจดี" },
  });
});

// POST: สร้างข้อมูลใหม่
app.post("/api/v1/students", (req, res) => {
  const { name } = req.body;

  if (!name) {
    return res.status(400).json({ message: "กรุณาระบุชื่อนิสิต" });
  }

  res.status(201).json({
    message: "เพิ่มข้อมูลนิสิตสำเร็จ",
    data: { id: 3, name },
  });
});

// PUT: แก้ไขข้อมูลทั้งหมด
app.put("/api/v1/students/:id", (req, res) => {
  const studentId = req.params.id;
  const { name } = req.body;
  res.status(200).json({
    message: `แก้ไขข้อมูลนิสิตรหัส ${studentId} สำเร็จ`,
    data: { id: Number(studentId), name },
  });
});

// DELETE: ลบข้อมูล
app.delete("/api/v1/students/:id", (req, res) => {
  const studentId = req.params.id;
  res.status(200).json({
    message: `ลบข้อมูลนิสิตรหัส ${studentId} สำเร็จ`,
  });
});
```

### 4.3 การอ่านค่าจาก Query String

```javascript
// ตัวอย่าง: GET /api/v1/students?page=2&limit=10
app.get("/api/v1/students", (req, res) => {
  const page = req.query.page || 1;
  const limit = req.query.limit || 10;

  res.status(200).json({
    message: "ดึงข้อมูลสำเร็จ",
    pagination: { page: Number(page), limit: Number(limit) },
  });
});
```

หมายเหตุ: เทคนิคการทำ pagination, filtering และ sorting อย่างสมบูรณ์จะกล่าวถึงในรายละเอียดในสัปดาห์ที่ 7 (Client-Oriented API Design)

### 4.4 การจัดกลุ่ม Route ด้วย Router

เมื่อโปรเจกต์มีขนาดใหญ่ขึ้น การรวม route ทั้งหมดไว้ในไฟล์เดียวจะทำให้ดูแลรักษายาก จึงควรแยก route ออกเป็นโมดูลย่อยด้วย `express.Router()`

ไฟล์ `routes/students.js`

```javascript
const express = require("express");
const router = express.Router();

router.get("/", (req, res) => {
  res.status(200).json({ message: "รายการนิสิตทั้งหมด" });
});

router.get("/:id", (req, res) => {
  res.status(200).json({ message: `นิสิตรหัส ${req.params.id}` });
});

module.exports = router;
```

ไฟล์ `index.js`

```javascript
const express = require("express");
const studentRoutes = require("./routes/students");

const app = express();
app.use(express.json());

// ทุก route ใน studentRoutes จะขึ้นต้นด้วย /api/v1/students
app.use("/api/v1/students", studentRoutes);

app.listen(3000, () => console.log("Server running on port 3000"));
```

การจัดโครงสร้างลักษณะนี้เป็นแนวปฏิบัติมาตรฐานที่จะใช้ต่อเนื่องตลอดรายวิชา

## 5. ตัวอย่างการทดสอบด้วย Postman

เมื่อสร้าง route เสร็จแล้ว ควรทดสอบการทำงานของ API ด้วยเครื่องมือ เช่น Postman แทนการทดสอบผ่านเบราว์เซอร์เพียงอย่างเดียว เนื่องจากเบราว์เซอร์ส่ง GET request ได้สะดวก แต่ไม่สามารถส่ง POST, PUT, PATCH, DELETE พร้อม body ได้โดยตรง

ตัวอย่างขั้นตอนการทดสอบ POST request ด้วย Postman

1. เลือก Method เป็น `POST`
2. ระบุ URL เป็น `http://localhost:3000/api/v1/students`
3. ไปที่แท็บ `Headers` และตั้งค่า `Content-Type: application/json`
4. ไปที่แท็บ `Body` เลือก `raw` และรูปแบบ `JSON` จากนั้นใส่ข้อมูล

```json
{
  "name": "สมหญิง รักเรียน"
}
```

5. กดปุ่ม `Send` และตรวจสอบผลลัพธ์ที่ได้รับกลับ ควรได้ Status Code `201 Created` พร้อมข้อมูลใน body ตามที่กำหนดไว้ในโค้ด

## สรุปเนื้อหาสำคัญ

1. HTTP เป็นโพรโทคอลแบบ stateless ที่ทำงานตามรูปแบบ request-response โดยมีขั้นตอนตั้งแต่การเชื่อมต่อ TCP จนถึงการส่งผลลัพธ์กลับ
2. HTTP Request ประกอบด้วย Request Line, Headers และ Body ส่วน HTTP Response ประกอบด้วย Status Line, Headers และ Body
3. การเลือกใช้ HTTP Method และ Status Code อย่างถูกต้องเป็นพื้นฐานสำคัญของการออกแบบ API ที่ดี
4. Node.js คือ runtime สำหรับรัน JavaScript ฝั่งเซิร์ฟเวอร์ ส่วน Express คือเฟรมเวิร์กที่ช่วยลดความซับซ้อนในการสร้าง HTTP server
5. การจัดกลุ่ม route ด้วย `express.Router()` ช่วยให้โครงสร้างโปรเจกต์เป็นระเบียบและดูแลรักษาง่าย

## คำถามท้ายบท

1. จงอธิบายความหมายของคำว่า HTTP เป็นโพรโทคอลแบบ stateless พร้อมยกตัวอย่างผลกระทบที่เกิดขึ้นต่อการออกแบบระบบ Backend
2. จงเรียงลำดับขั้นตอนของ HTTP lifecycle ตั้งแต่ไคลเอนต์เริ่มส่งคำขอจนถึงได้รับผลลัพธ์กลับ
3. HTTP Method ใดต่อไปนี้ควรมีคุณสมบัติ idempotent (เรียกซ้ำกี่ครั้งผลลัพธ์สุดท้ายก็เหมือนเดิม) จงอธิบายเหตุผลประกอบ: GET, POST, PUT, DELETE
4. หากเซิร์ฟเวอร์ประมวลผลคำขอสำเร็จและมีการสร้างข้อมูลใหม่ ควรตอบกลับด้วย Status Code ใด และเพราะเหตุใดจึงไม่ควรใช้ Status Code 200 ในกรณีนี้
5. จงเขียนโค้ด Express เพื่อสร้าง route รับคำขอ `GET /api/v1/courses/:courseId` ที่คืนค่าข้อมูลรายวิชาในรูปแบบ JSON พร้อมจัดการกรณีที่ไม่พบข้อมูล (ให้ตอบกลับ Status Code 404)
6. เหตุใดจึงควรใช้เครื่องมือ เช่น Postman ในการทดสอบ API แทนการทดสอบผ่านเว็บเบราว์เซอร์เพียงอย่างเดียว
7. จงอธิบายประโยชน์ของการใช้ `express.Router()` ในการจัดโครงสร้างโปรเจกต์ที่มีขนาดใหญ่
